# Pentest Notes — HackTheBox: Spectra (10.10.10.229)
# Date: 2024-03-15
# Tester: r00t

## Initial Recon

Started with a full port scan against 10.10.10.229. Found three open ports:
22 (SSH), 80 (HTTP), 3306 (MySQL). The web server on port 80 redirected to
spectra.htb so I added it to /etc/hosts.

## Web Enumeration

Ran gobuster against http://spectra.htb and found two interesting directories:
/main (WordPress installation) and /testing (another WordPress instance with
debug mode enabled and database credentials exposed in wp-config.php).

Credentials found in wp-config.php:
- DB user: devtest
- DB password: devteam01

## WordPress Exploitation

Used wpscan to enumerate users on the /main WordPress installation.
Found user: administrator

Logged into WordPress admin panel at http://spectra.htb/main/wp-admin
using credentials administrator:devteam01 (password reused from database).

Uploaded a PHP reverse shell via the theme editor (Appearance > Theme Editor).
Modified the 404.php template with a pentestmonkey reverse shell pointing
to 10.10.14.5:4444.

Set up netcat listener and triggered the shell by visiting a non-existent page.
Got a shell as nginx user.

## Privilege Escalation

Ran linpeas on the target. Found interesting cronjob running as katie user
that executed /usr/local/share/mypower — a world-writable script.

Replaced /usr/local/share/mypower with a bash reverse shell.
Got shell as katie.

Found user flag in /home/katie/user.txt: HTB{sp3ctr4_w0rdpr3ss_pwn3d}

Checked sudo permissions for katie:
sudo -l showed: (ALL) NOPASSWD: /sbin/initctl

Used initctl to start a custom service that ran bash as root.
Got root shell.

Root flag in /root/root.txt: HTB{1n1tctl_pr1v3sc_f0r_th3_w1n}

## Summary

- WordPress credentials reuse from exposed wp-config.php
- RCE via theme editor PHP upload
- PrivEsc via writable script in cronjob + initctl sudo abuse
